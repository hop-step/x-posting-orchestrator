# 公開前の機密情報監査

2026-10-07にGitHub公開用のソースとGit履歴を確認しました。

## 確認した範囲

- 公開対象の追跡済みファイルと追加ファイル
- 全ブランチ・タグから到達可能なGit履歴（既存8コミット）
- 履歴内の全196 blobと、手元の秘密設定に含まれる実キー等との完全一致
- `.env`、`.dev.vars`、`.secrets/`、秘密鍵、DB、配布ZIPの追跡履歴
- 本番URL、D1 ID、アカウントIDなどの環境固有情報

## 結果と対応

- Gitleaks 8.30.1で履歴と公開対象ファイルを走査しました。
- 検出された1件は`test/unit/api-client-route.test.ts`の固定ダミーpepperでした。テスト用の決まった文字列で、本番の秘密値ではありません。
- `.gitleaks.toml`でそのファイルのその固定値だけを除外しています。他のキーやファイルは除外していません。
- 手元の秘密設定に含まれる値と、公開対象・履歴内blobの一致は0件でした。
- `.secrets/`のBasic認証・外部AIキー・配布ZIPなどはGit管理外で、追跡履歴にもありませんでした。
- `.dev.vars`、ローカル設定、DB、秘密鍵、ログ、ZIPを`.gitignore`へ追加しました。
- 公開時点の`wrangler.jsonc`はD1 IDとWorker URLをプレースホルダーへ置き換えました。
- AIドキュメントと発行コマンドから特定の本番ホストへの自動接続を除き、管理者指定のAPI URLを使う形にしました。

既存履歴には従来のWorker URLとD1リソースIDが残っています。これらは認証情報ではなく、IDだけでD1へ接続することはできません。秘密値を含む履歴は見つからなかったため、既存の開発履歴を保持しています。コミットの著者名・メールアドレスもGitの標準メタデータとして公開されます。

この監査は秘密情報の公開混入を調べたもので、アプリケーション全体のセキュリティ保証ではありません。今後のコミット前にも`gitleaks git . --staged --redact`で確認してください。秘密値を誤ってコミットした場合は、履歴から削除するだけでなく該当キーの失効・再発行が必要です。
